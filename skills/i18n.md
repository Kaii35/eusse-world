# Skill — Internacionalización

## Objetivo

Que añadir un idioma sea añadir un archivo, y que ningún texto quede fuera del sistema.

## Buenas prácticas

- **Ningún literal en el código.** Regla de ESLint que rompe el build desde el primer
  commit. Si se deja para después, nunca se hace.
- **Nunca concatenes fragmentos traducidos.** El orden de las palabras cambia entre idiomas.
  Usa ICU con parámetros.
- **Plurales con ICU**, no con `if (n === 1)`. El español tiene 2 formas; el árabe, 6.
- **`Intl` para fechas, números y monedas.** Nunca formateo manual.
- **La moneda es un dato del importe, no del idioma.** Un usuario en inglés puede comprar
  en pesos.
- **Claves por propósito**, no por contenido: `cart.emptyState.title`.
- **Prueba con textos largos.** El alemán suele ser un 30% más largo y revela los desbordes.
- **Paridad de claves verificada en CI.**

## Errores comunes

| Error                                          | Consecuencia                                |
| ---------------------------------------------- | ------------------------------------------- |
| Texto escrito en el JSX                        | Bloquea la traducción; se acumula rápido    |
| `"Tienes " + n + " productos"`                 | Intraducible; el orden cambia               |
| `n === 1 ? 'producto' : 'productos'`           | Falla en idiomas con más formas plurales    |
| `date.toLocaleDateString()` sin locale         | Formato del servidor, no del usuario        |
| Formato de moneda codificado (`"$" + x`)       | Símbolo, posición y separadores incorrectos |
| Claves con el texto español                    | Al cambiar el texto, la clave miente        |
| Probar sólo con textos cortos                  | Desbordes al traducir                       |
| Traducir en el servidor y devolverlo en la API | La API deja de ser agnóstica                |
| Falta una clave y muestra la clave cruda       | Se ve `cart.empty.title` en producción      |
| Texto dentro de imágenes                       | Intraducible                                |

## Patrones

**Interpolación con ICU**

```json
{
  "cart": {
    "itemCount": "{count, plural, =0 {Tu carrito está vacío} one {# producto} other {# productos}}",
    "addedToCart": "Añadido: {quantity} × {productName}"
  }
}
```

```
t('cart.itemCount', { count })
t('cart.addedToCart', { quantity: 10, productName: 'Taladro X' })
```

**Formateo con `Intl`**

```
export function formatMoney(money: Money, locale: string) {
  return new Intl.NumberFormat(locale, {
    style: 'currency', currency: money.currency, minimumFractionDigits: 0,
  }).format(money.amount / 100)
}
```

La moneda sale del `Money`, no del locale.

**Errores de dominio localizados por código**

```
// El backend devuelve code + meta; el frontend traduce.
t(`errors.${error.code}`, error.meta)
// errors.CART_QTY_NOT_MULTIPLE:
//   "{sku} se vende en cajas de {qtyIncrement} unidades"
```

La API no traduce; devuelve datos. El frontend compone el mensaje en el idioma del usuario.

**Verificación de paridad en CI** — script que compara las claves de `es.json` y `en.json`
y falla si alguna falta en cualquiera de los dos.

**Pseudo-localización en preview** — `[!!! Ãññadïr al carrïtö !!!]` revela textos sin
traducir y desbordes de layout antes de que llegue la traducción real.

## Antipatrones

- **Traducción automática sin revisión** en textos comerciales o legales.
- **Un archivo gigante de mensajes** sin estructura por feature.
- **Claves genéricas reutilizadas** (`common.yes`) donde el contexto cambia la traducción.
- **HTML dentro de la traducción**: usa `rich text` de next-intl.
- **Idioma detectado sólo por IP**: un colombiano en Miami quiere español.
- **Traducir en la capa de API**: acopla el backend a la presentación.

## Ejemplos

**Bien**

```
{t('order.summary', {
  count: lines.length,
  total: formatMoney(order.total, locale),
  date: formatDate(order.placedAt, locale),
})}
```

**Mal**

```
`Pedido de ${lines.length} productos por $${order.total} el ${order.placedAt}`
```

Sin traducción, sin plural, sin formato de moneda, sin zona horaria.

## Convenciones

- `messages/es.json` y `messages/en.json` por app.
- Claves: `<feature>.<componente>.<elemento>` en `camelCase`.
- Rutas con prefijo de locale: `/es/...`, `/en/...`.
- `es` por defecto; `en` como alternativa.
- `@eusse/i18n` expone los formateadores compartidos.
- `lang` correcto en `<html>`; `hreflang` coordinado con SEO.

## Checklist

- [ ] Cero literales en el código (lint activo)
- [ ] Paridad de claves verificada en CI
- [ ] Claves semánticas, organizadas por feature
- [ ] Plurales con ICU
- [ ] Interpolación con parámetros, sin concatenación
- [ ] Fechas y números con `Intl`
- [ ] Moneda según el importe, no según el idioma
- [ ] Zona horaria del usuario al formatear
- [ ] Probado con textos largos y con pseudo-localización
- [ ] Sin desbordes ni truncados inesperados
- [ ] `lang` y `hreflang` correctos
- [ ] Locale persistido en la preferencia del usuario
- [ ] Errores de dominio localizados por `code`
- [ ] Emails transaccionales localizados
- [ ] Revisión por hablante nativo en textos de cara al cliente
